# Decisiones del bibliotecario

| Fecha | Agente | Decisión | Alternativa descartada | Por qué |
|---|---|---|---|---|
| 2026-10-20 | bibliotecario | Script determinista; sin modelo ni `prompt.md`. | Haiku redactando el cuerpo del PR. | Todo es mecánico (nombres, catálogo, git). El cuerpo del PR es una plantilla que solo cita la noticia (medio, título, fecha, URL). Si luego se quiere texto libre, se agrega prompt con `ClienteFalso` en tests. |
| 2026-10-20 | bibliotecario | Dry-run por defecto; el dry-run no escribe archivos (ni en `tareas/`), solo valida y calcula en memoria. `--ejecutar` es explícito. `--sin-remoto` omite push y PR. | Escribir archivos en dry-run. | Evita ensuciar el repo real; los comandos impresos son los que se ejecutarían. |
| 2026-10-20 | bibliotecario | Se archiva lo que está en `verificada` o `publicada`. | Solo `publicada`. | El PR semanal es la revisión humana 2 (GOB01 §2) y el merge lo deja en `publicada`; exigir `publicada` antes del PR sería circular. Lectura conservadora: nunca antes de `verificada`. Revisar con Carlos si el orquestador debe marcar `publicada` antes o después del merge. |
| 2026-10-20 | bibliotecario | Dos commits por tarea: archivos de la tarea, luego catálogo con el sha real del primero. | Un solo commit con commit provisional. | El contrato exige `commit` hex; un commit no puede contener su propio hash. En dry-run se muestra `0000000`. |
| 2026-10-20 | bibliotecario | Archivos siempre versionados, incluida la evaluación: `evaluacion_vX.0_AAAA-MM-DD.json`. | `evaluacion.json` sin versión (como en el ejemplo de catálogo). | Una v2 en la misma carpeta sobrescribiría `evaluacion.json`; GOB01 §4 exige conservar la v1. El contrato admite cualquier nombre. |
| 2026-10-20 | bibliotecario | Prefijo de commit `pipeline:`. | `tareas:` (el encargo lo permitía). | CLAUDE.md no lo lista; se usa uno listado. Configurable en `config.yaml`. Pendiente: que Carlos decida si agrega `tareas:`. |
| 2026-10-20 | bibliotecario | Una rama por semana ISO (`tareas/semana-AAAA-Www`); si existe se reutiliza y, si hay PR abierto, el push lo actualiza; si no, `gh pr create`. | Una rama y PR por tarea. | GOB01 §2: PR semanal. |
| 2026-10-20 | bibliotecario | Rechaza: catálogo existente que no valida (p. ej. licencia distinta), versión <= la publicada, archivo existente, RUB01 bajo el umbral, texto literal > 25 palabras (si se da `--texto-noticia`), escenarios sin corrida (si se dan trazas). Nunca modifica nada al rechazar. | Corregir o reescribir el catálogo corrupto. | Un catálogo inválido es señal de manipulación o error; lo resuelve un humano. |
| 2026-10-20 | bibliotecario | `GH_TOKEN` (o `GITHUB_TOKEN`) solo se comprueba presente en `--ejecutar` con remoto; `gh` lo lee del entorno. No se imprime ni se pasa por argumentos. | Pasar el token por parámetro. | Invariante 7. |
| 2026-10-20 | bibliotecario | `--ejecutar` exige índice de git limpio y solo hace `git add` de rutas explícitas. | `git add -A`. | No arrastrar trabajo ajeno a un PR público. |
